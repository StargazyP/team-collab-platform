# 접속 문제 (404 / 접근 불가)

## https://jangdonggun.iptime.org:3000 접근 시 404

### 1. dev 서버가 외부에서 접근 가능하도록 실행하기

- **원인**: `next dev`가 기본으로 `127.0.0.1`에만 바인딩되면, 같은 PC에서만 접속 가능하고 다른 기기나 도메인으로는 연결이 안 되거나 다른 서비스가 404를 줄 수 있음.
- **조치**: `package.json`의 `dev` 스크립트에 **`-H 0.0.0.0`** 추가됨.  
  → `npm run dev` 시 모든 네트워크 인터페이스에서 접속 가능.

```bash
cd user && npm run dev
```

### 2. HTTPS 인증서와 도메인 불일치

- **현재**: `localhost+2.pem`은 **localhost**용 인증서임.
- **접속**: `https://jangdonggun.iptime.org:3000`으로 접속하면 브라우저에서 **인증서 경고**가 뜰 수 있음. (404와는 별개)
- **선택**:
  - 경고를 무시하고 “위험 감수하고 접속” 후 404 여부 확인.
  - 또는 **같은 PC에서만** `https://localhost:3000`으로 접속해 404가 나는지 확인.

### 3. 404가 나는 경우 점검 순서

| 확인 항목 | 설명 |
|----------|------|
| **실제 응답 주체** | 404가 **Next.js 앱**에서 나는지, **공유기/nginx** 등 다른 서비스에서 나는지 구분. 브라우저 개발자 도구 → Network에서 응답 본문/헤더 확인. |
| **포트 포워딩** | 공유기(iptime)에서 **외부 3000 → PC의 3000**으로 포워딩되어 있는지 확인. |
| **방화벽** | PC 방화벽에서 **인바운드 3000** 허용 여부 확인. |
| **프록시(nginx 등)** | 443으로 들어온 요청을 3000으로 넘기는 경우, `proxy_pass`와 `Host`/`X-Forwarded-Proto` 설정이 맞는지 확인. |

### 4. HTTP로 먼저 확인

- HTTPS 인증서 문제를 제외하려면 **HTTP**로 테스트:
  - 같은 PC: `http://localhost:3000`
  - 같은 네트워크: `http://192.168.0.x:3000` (PC의 내부 IP)
  - 여기서 404가 나면 Next.js 앱/라우팅 문제, 여기서는 되는데 도메인:3000에서만 404면 네트워크/프록시 쪽 점검.

### 5. Next.js 앱 루트(/) 동작

- 루트 `/`는 **로그인 여부에 따라** `/login` 또는 `/workspaces`로 **리다이렉트**만 함.  
- 따라서 정상이면 **404를 반환하지 않음**. 404가 나온다면 위 1~4를 먼저 확인한 뒤, 필요 시 서버/프록시 로그와 Next.js 터미널 로그를 함께 확인하는 것이 좋음.
